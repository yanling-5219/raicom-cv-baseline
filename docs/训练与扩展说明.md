# 训练与扩展说明（队友必看）

这份文档讲三件事：基线是怎么训出来的、参数怎么调、赛题落地后怎么往上加功能。

## 一、基线是怎么跑通的

### 1. 数据：合成小数据集

`python scripts/make_synth_data.py` 会生成 YOLO 格式数据集：

- `data/synth/train/`：80 张训练图，`data/synth/val/`：20 张验证图
- 每张图 320×320，1–4 个随机矩形 / 圆形，标签是归一化的 `(class, x_center, y_center, w, h)`
- 类别：`0=rect`（矩形）、`1=circle`（圆形），配置在 `configs/data.yaml`

为什么用合成数据：赛题未定，先用可复现的小数据把"数据 → 训练 → 推理"整条链路跑通。
换真实数据时，只要按同样的 YOLO 格式组织目录，改 `data.yaml` 里的 `path` 和 `names` 就行。

### 2. 训练：CPU 小闭环

```bash
python scripts/train.py --epochs 10
```

关键参数（都在 `scripts/train.py` 里可调）：

| 参数 | 基线值 | 说明 |
|---|---|---|
| epochs | 10 | 合成小数据 10 轮就收敛；真实数据一般 50–300 |
| imgsz | 320 | 训练图片尺寸；越大越准越慢，640 是常用值 |
| batch | 16 | CPU 上别太大，16 安全 |
| device | cpu | 有 GPU 的机器改成 `0` |
| workers | 2 | 数据加载线程数 |

产物：`runs/synth_baseline/weights/best.pt`（验证集上最好的权重）+ `results.png`（loss/mAP 曲线）。

### 3. 推理：图片目录 → 标注结果

```bash
# 官方预训练权重（80 类 COCO，首次运行自动下载）
python scripts/infer.py
# 自训权重（2 类 rect/circle）
python scripts/infer.py --weights runs/synth_baseline/weights/best.pt
```

`--conf` 调置信度阈值（默认 0.25），`--imgsz` 调推理尺寸。标注图存 `outputs/`，
终端会打印每张图的检出目标和置信度。

## 二、调参速查

- **欠拟合**（train loss 下不去）：加 epochs、加数据、把 imgsz 调大
- **过拟合**（train 好、val 差）：加数据增强（ultralytics 默认已开）、加数据量、早停
- **小目标检不出**：imgsz 调大（640/1280）、检查标注框是否准确
- **速度慢**：换 yolov8n（已是最小）、imgsz 调小、导出 ONNX/TensorRT（见下）

## 三、赛题落地后的扩展路线

赛题一定下来，按这个顺序加功能，每一步都是独立可验证的：

1. **换数据**：按 YOLO 格式标注赛题图片（推荐 labelImg / X-AnyLabeling），
   更新 `configs/data.yaml` 的 `names`，先跑 10 个 epoch 看链路通不通
2. **调参**：按上面的速查表把 mAP 拉上去，目标是在验证集上稳定
3. **推理接入**：把 `infer.py` 的单图推理改成视频流 / 摄像头循环，
   参考 ultralytics 的 `model.predict(source=0)` 写法
4. **后处理**：按赛题需求加——目标跟踪（BoT-SORT）、坐标换算、串口/网络上报
5. **部署优化**：`model.export(format="onnx")` 转 ONNX，CPU 推理再快几倍

## 四、常见问题

- **Q: pip 装 ultralytics 太慢？** A: 用国内镜像：`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple ultralytics`
- **Q: 训练时报内存不足？** A: 把 `--batch` 调小（8 或 4），或把 `--imgsz` 调小
- **Q: 官方权重下载失败？** A: 手动从 GitHub ultralytics release 下载 `yolov8n.pt` 放到仓库根目录
- **Q: 推理一张图要多久？** A: CPU 上 yolov8n 约 0.1–0.3 秒/张（640 尺寸），够基线验证用
